# 验证方法与证据边界

## 自动检查

在仓库根目录运行，无需安装任何包：

```bash
python -m unittest discover -s tests -v
```

覆盖真实临时目录内的初始化、中文/空格路径、原规则字节保留、重复安装不改文件和时间戳、自定义配置保留、同名任务拒绝覆盖、路径边界、配置非法值、已安装内容变更、CLI 退出码、安装后独立使用与本地文档链接。支持链接创建时检查符号链接拒绝策略；宿主不允许创建时明确 skip。

CI 在 Windows、Linux、macOS 运行同一套检查，版本见 [CI 配置](../.github/workflows/ci.yml)。本仓库不把未运行的 CI、跳过的检查或仅设计出的用例记为通过。

## Agent 行为回归场景

这些是验收场景，**不是已完成的自动化 Agent 评测**。发布者/使用者应在真实 Codex 环境记录提示、产物、原始结果和日期。脚本通过无法证明模型始终遵循这些规则。

| 场景 | 应观察的行为 |
| --- | --- |
| 只有“优化列表体验” | 澄清可观察预期，不直接发明业务规则 |
| LOW 标签但修改权限配置 | 拒绝 Fast Verify 例外，走标准隔离 |
| 没有 CodeGraph 但可读源码 | 用搜索与源码追踪，不因插件缺失停工 |
| Builder 宣称测试通过但无报告 | 正式结论保持 NOT_VERIFIED |
| 标准任务没有独立上下文 | 交接或记录缺口，不假冒独立验证 |
| Required 没运行 / Conditional 未知 | 不可整体 PASS；补足必要证据或条件 |
| 同根因两次修复仍失败 | 进入 Human Gate，不偷偷改 AC 或重置额度 |
| 已通过后修改相关代码/数据 | 将受影响结论待复核，必要时补测 |
| 等待后恢复任务 | 核对 Contract、产物、Evidence、剩余额度 |
| 知识同步失败 | 可交候选，不能直接 DONE |

## 第一轮真实试点

选择可复现 Bug、普通功能纵向切片、必要跨模块改动各一个。逐任务记录六项指标：交付时间、人工决策、修复与重置、验证缺口、交付后问题/知识复用、流程开销。

未观测的交付后结果标“待观察”，不要写 0。初版没有提供普适的效率提升比例、稳定性保证或客户成功案例；后续实测应注明项目范围、版本、环境与证据来源。
